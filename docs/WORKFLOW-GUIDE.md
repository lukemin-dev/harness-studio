# 분석부터 검수까지 사용하기

## 적용한 구성

GIIP FDE Agent의 역할·규칙·작업 절차 분리 방식을 참고해 작업 지시 양식을 자체 작성했습니다.
GIIP 소스나 실행 스크립트를 복사하거나 실행하지 않았습니다.

- 참고: https://github.com/LowyShin/giip-fde-agent
- 로컬 검토: docs/02-design/agent-components/overview.md,
  slack-bot/package.json, slack-bot/index.js의 실행 관련 부분,
  .agent/scripts/launch_subsession.ps1의 작업 선택·역할 처리 부분.
- 전체 코드 보안 감사나 GIIP 실행 검증은 하지 않았습니다.

## 사용 순서

1. 프로젝트 설정에서 수정 허용 파일과 신뢰하는 검사 명령을 지정합니다.
2. **새 작업 → 작업 도우미**에서 분석, 문법 전환, 검수 중 하나를 선택합니다.
3. 대상 파일의 저장소 기준 경로나 메뉴를 입력하고 **지시 채우기**를 누릅니다.
4. 생성된 제목·지시·완료 기준을 읽고 필요한 부분을 수정한 뒤 등록합니다.
5. 실행 시 별도 작업 폴더에서 처리합니다. 등록 자체는 실행하지 않습니다.
6. 결과에서 변경 내역·검사·독립 검수 결과를 확인합니다.

분석과 검수 양식은 소스를 변경하지 않고 보고서를 생성합니다.
각각 `harness-reports/analysis.md`, `harness-reports/audit.md`를 허용 파일에 추가하세요.
허용 파일은 자동 확대하지 않습니다. 프로젝트 규칙과 양식이 충돌하면 실행 전에 조정하세요.
문법 전환 양식은 대상 XML만 허용하고, 검사 명령에는 XML 파싱·기존 계약 비교 등을 등록하세요.

## 역할과 실제 실행의 구분

양식은 작업자의 역할과 보고 형식을 지정합니다. 세 명의 에이전트를 자동으로 병렬 실행하는 기능은 아닙니다.
기존 실행 흐름인 작업 담당 → 등록된 검사 → 별도 검수 담당을 사용합니다.
다음 단계의 작업은 결과를 확인한 뒤 별도로 등록합니다.

## 범위와 제한

- DB2 제외와 기존 구조 유지 규칙을 기본 지시에 포함합니다.
- 정적 검사 성공은 실제 DB·화면 검증 성공을 뜻하지 않습니다.
- 실제 작업 실행에 대한 도구 정책·인증·사용량 제한은 그대로 적용됩니다.
- 원격 로그인, Slack 연결, 자동 Git push 기능은 이번 변경에 포함하지 않습니다.
- 회사 소스·접속정보·실행 기록은 관리 프로그램의 Git 저장소에 올리지 않습니다.
