# Harness Studio

**작업 지시 → Codex 수정 → 자동 검사 → 별도 Codex 검수 → 결과 보고**를 관리하는 로컬 웹 프로그램입니다.

Python 표준 라이브러리만 사용합니다. 서버용 서비스나 별도 AI API 구독 없이, 설치된 Codex CLI의 로그인을 사용합니다. ChatGPT 요금제의 Codex 사용량 제한은 그대로 적용됩니다.

## 시작하기

필수: Python 3.10 이상, Git. 실제 AI 실행에는 Codex CLI 설치 및 `codex login`이 필요합니다.

```powershell
git clone <이 저장소의 주소>
cd harness-studio
python -m harness.app --open
```

Windows에서는 `start.cmd`를 더블클릭하거나 `start.ps1`을 실행해도 됩니다.
일반 Python을 먼저 찾고, 없으면 설치된 Codex 번들 Python을 찾습니다. Python을 별도로 설치한 경우:

```powershell
.\start.ps1 -PythonPath "C:\경로\python.exe"
```

브라우저 주소: **http://127.0.0.1:8765**

다른 포트나 데이터 폴더:

```powershell
python -m harness.app --port 8766 --data "C:\HarnessData" --open
```

## 처음 사용하는 순서

1. **샘플 준비**: 독립된 계산기 예제를 만듭니다.
2. 작업 카드의 **데모**: AI 호출 없이 화면과 실행 단계를 확인합니다.
3. **Codex 실행**: 실제로 샘플 코드에 설명을 추가하고 테스트·검수를 실행합니다.
4. **프로젝트 연결**: 작업할 Git 저장소의 최상위 폴더를 등록합니다.
5. **작업 등록**: 할 일과 완료 기준을 적고 실행합니다.
6. 결과의 **변경 내용 / 검사 결과 / 보고서**를 확인합니다.

프로젝트는 최소 한 번 커밋되어 있어야 하며, 실제 실행을 시작할 때 미커밋 변경이 없어야 합니다. 실행별로 별도 Git worktree를 만들어 현재 HEAD의 코드를 수정합니다.

## 지시 예시

**작업 지시**

> 지정한 XML의 MSSQL 문자열 연결 문법을 PostgreSQL 문법으로 변경해 주세요. 기존 namespace, SQL ID, 파라미터 이름, 조회 조건과 결과 의미를 유지하세요. DB2 관련 파일은 수정하지 마세요.

**완료 기준**

> 수정 범위는 지정 XML 한 개입니다. XML 파싱 검사를 통과하고, 변경 전후 SQL ID가 같아야 합니다. 실제 DB를 사용하지 않았다면 실행 검증 대기로 보고해 주세요.

위 조건을 프로그램이 모두 자동 판정하는 것은 아닙니다. 파일 범위는 코드로 검사하지만 SQL 의미·기능 동일성은 등록한 검사와 검수 담당이 확인합니다. 실제 DB·화면 검증은 별도로 수행해야 합니다.

## 프로젝트 설정

| 항목 | 작성 방법 |
|---|---|
| 수정 허용 파일 | 저장소 기준 상대 경로, 한 줄에 하나. 예: `src/mapper/common.xml` |
| 검사 명령 | 명령과 인자를 JSON 배열로 입력 |
| 재수정 횟수 | 검사 또는 검수 실패 후 추가 시도 0~3회 |
| 제한시간 | 작업 전체 10~7200초 |
| 작업 규칙 | 구조 유지, 변경 제외 파일, 기존 기능 유지 등 |
| Codex 모델 | 선택 사항. 비우면 CLI 기본 설정, 입력하면 이 프로젝트 실행에만 적용 |

검사 명령 예시:

```json
[
  ["{python}", "-m", "unittest", "discover", "-s", "tests", "-v"]
]
```

`{python}`은 관리 프로그램 실행에 사용한 Python으로 바뀝니다. 명령은 별도 작업 폴더에서 실행됩니다. 셸 문법(`&&`, 리다이렉션 등)을 자동 해석하지 않습니다. Windows의 배치 프로그램은 필요한 경우 명시적인 실행기를 지정해야 합니다.

허용 패턴에는 Python `fnmatch` 규칙을 사용하며 `*`는 `/`도 포함할 수 있습니다. 좁은 범위가 필요하면 파일을 직접 지정하세요. 허용 파일 검사는 실행 후 변경을 탐지하는 장치이며 운영체제 수준의 접근 제한이 아닙니다.

## 상태 읽기

| 상태 | 의미 |
|---|---|
| 소스·검사 통과 | 등록된 검사 명령 성공 + 독립 검수 통과 |
| 소스 검수 통과 | 독립 검수 통과, 검사 명령은 미등록 |
| 데모 완료 | 흐름 시뮬레이션만 완료. 실제 검증 아님 |
| 검증 실패 | 검사/검수 실패, 재시도 한도 도달 |
| 확인 필요 | 허용 범위 위반, 인증 오류, 시간 초과 등으로 중단 |
| 종료로 중단 | 관리 프로그램 재시작 시 발견된 미완료 실행 |

Codex 설치가 표시되어도 인증 성공까지 확인한 것은 아닙니다. 터미널에서 `codex login status`로 확인하세요. 인증·사용량 오류는 무한 재시도하지 않습니다.

## 결과 반영과 Git

원본 저장소에 자동 병합하거나 자동 push하지 않습니다. 결과 화면의 작업 폴더에서 수정 내용을 검토하고, 필요한 검증을 완료한 후 직접 커밋·병합하세요. 작업 폴더는 보존되며 자동 삭제하지 않습니다.

Harness Studio 자체를 Git에 올릴 때:

```powershell
git add .
git commit -m "Add Harness Studio"
git remote add origin <생성한 저장소 주소>
git push -u origin main
```

`.harness/`는 Git에서 제외됩니다. 여기에는 SQLite 작업 기록, 로그, 검수 결과, 별도 작업 폴더가 들어 있습니다. 다른 프로젝트의 파일·개인정보·인증정보를 이 저장소에 복사하지 마세요. 로컬 로그도 작업 내용이 포함될 수 있으므로 공유 전에 확인하세요.

## 검증

```powershell
python -m unittest discover -s tests -v
node --check harness/static/app.js
```

테스트는 임시 Git 저장소와 실제 검사 프로세스를 사용합니다. AI 호출만 대체하여 범위 위반, 실패 재시도, 원본 보존, 검수 중 변경, 중단, 시간 초과, HTTP 보호를 재현합니다. Node는 프런트엔드 문법 점검에만 필요하며 앱 실행에는 필요하지 않습니다.

## 구조

```text
harness/
  app.py          로컬 HTTP API, 시작·종료, 샘플 생성
  core.py         SQLite, Git 작업 폴더, 실행·중단·검수
  static/         한국어 관리 화면
tests/            자동 회귀 검사
start.ps1         Windows 실행 도우미
```

## 현재 범위와 제한

- 한 번에 한 작업을 실행하는 **개인용 로컬 관리자**입니다.
- 수정 담당과 검수 담당은 별도 Codex 실행이며 검수는 읽기 전용 모드를 요청합니다. 서로 다른 모델을 사용하는 구조는 아닙니다.
- Codex는 설치된 CLI의 설정을 사용합니다. Python 관리 프로그램 자체는 Codex 사용량을 조회하거나 비용을 계산하지 않습니다.
- 검사 명령은 사용자의 PC 권한으로 실행됩니다. 신뢰하는 저장소·명령만 등록하세요.
- worktree는 별도 디렉터리이며 완전한 보안 격리 환경은 아닙니다. Git에서 무시된 파일, 외부 서비스의 변경은 변경 파일 검사에 포함되지 않습니다.
- 프로세스 중단 기능을 제공하지만 PC 강제 종료 시 외부 프로세스가 남는 경우가 있으므로 확인이 필요합니다.
- DB·화면 검증 상태는 자동으로 통과 처리하지 않습니다.
- 로그 출력은 실행 명령별 최대 1,500개 조각으로 제한됩니다.
- 팀 계정, 원격 접속, 동시 실행, 자동 배포, 자동 PR 생성은 현재 범위에 포함하지 않습니다.
